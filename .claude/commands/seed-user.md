# Slash Command: seed-user

## Overview
The `seed-user` slash command generates and inserts a randomly created user record into the user database table. This is useful for development, testing, and seeding initial data.

## Command Name
```
/seed-user
```

## Description
Automatically creates a new user with randomly generated or provided details and inserts it into the `users` table.

## Functionality
When invoked, this command will:
1. Generate a new user record with the following fields:
   - **name**: A randomly generated full name
   - **email**: A randomly generated unique email address
   - **password**: A hashed password (securely generated)
   - **created_at**: Current timestamp (auto-set to the time of execution)

2. Validate the generated data to ensure all required fields are populated
3. Insert the new user record into the database `users` table
4. Return confirmation with the newly created user details (excluding the password)

## Usage

### Basic Usage
```
/seed-user
```
Creates a single new user with all fields auto-generated.

### Parameters
The command supports the following optional parameters:

| Parameter | Type | Description | Default |
|-----------|------|-------------|---------|
| `--name` | string | Custom user name instead of generated | Auto-generated |
| `--email` | string | Custom email instead of generated | Auto-generated |
| `--count` | number | Number of users to create (1-100) | 1 |

### Example Usage
```
/seed-user --name "John Doe" --email "john@example.com"
/seed-user --count 5
/seed-user --name "Jane Smith"
```

## Output Format
Upon successful execution, the command will return:

```
✓ User seeded successfully

User Details:
├─ ID: <auto-generated-id>
├─ Name: <generated-or-provided-name>
├─ Email: <generated-or-provided-email>
├─ Password: ••••••••••••••••
└─ Created At: <timestamp>
```

### Error Handling
- **Duplicate Email**: If the generated email already exists, the command will regenerate or notify the user
- **Invalid Input**: If custom parameters are provided in invalid format, an error message will be displayed
- **Database Error**: Any database connectivity issues will be reported with appropriate error messages

## Fields Populated

| Field | Type | Value |
|-------|------|-------|
| `name` | STRING | Randomly generated full name (e.g., "Sarah Johnson") |
| `email` | STRING | Randomly generated unique email (e.g., "user123456@example.com") |
| `password` | STRING | Securely hashed random password |
| `created_at` | TIMESTAMP | Current server time (auto-set) |

## Use Cases
- **Development**: Quickly populate the database with test users
- **Testing**: Create multiple users for integration testing
- **Prototyping**: Seed initial data for feature demonstrations
- **Database Setup**: Initialize user data in new environments

## Permissions Required
- Write access to the `users` table
- Database connection permissions

## Notes
- All generated passwords are hashed using the application's standard password hashing algorithm
- Each generated email is unique and will not conflict with existing records
- The `created_at` timestamp is set server-side to ensure consistency
- No actual emails are sent during seed creation
